왜 도구와 알고리즘을 따로 배우나

1. 도구가 프로젝트를 좌우한다

교안은 도구 선택이 분석 프로젝트의 성공을 결정하는 핵심 요소라고 말합니다. 맞지 않는 도구를 고르면 분석 효율과 결과 품질이 크게 떨어집니다.[1]

2. 규칙을 누가 만드는가

전통적 프로그래밍은 사람이 규칙을 적고, 머신러닝은 데이터와 과거 결과에서 규칙을 찾습니다. 같은 대출 심사라도 만드는 방식이 다릅니다.[1]

3. 문제 유형이 모델을 고른다

3주차에서 정한 분류·예측·군집·연관·최적화 유형마다 어울리는 알고리즘과 평가 지표가 있습니다.[1]

규칙 기반과 머신러닝 — 신용대출 심사

비교: 사람이 쓴 규칙 vs 데이터에서 배운 규칙교안 사례: 은행 신용대출

이 칸의 결론사람이 쓴 규칙은 설명이 쉽고, 머신러닝은 복잡한 경계를 잘 따라갑니다. 둘 중 무엇을 쓸지는 설명이 필요한지에 달렸습니다.

먼저왜 이 모델을 쓰나

은행이 대출을 심사할 때, 예전에는 사람이 "연소득 3,000만 원 이상이고 연체가 없으면 승인" 같은 규칙을 직접 적었습니다. 그런데 고객 특성이 수십 가지가 되면 사람이 모든 조합의 규칙을 적을 수 없습니다. 그래서 과거 승인·연체 기록을 보고 규칙을 컴퓨터가 찾게 하는 것이 머신러닝입니다.

쉽게 말하면 수학 문제는 "식을 줄 테니 답을 구하라"이고, 머신러닝은 "답을 잔뜩 줄 테니 식을 구하라"입니다.

f(x)니 함수니… 머신러닝이 수학 시간의 함수랑 무슨 상관이에요?

학교 수학으로 보면 중학교 일차함수 y = ax + b에서, a와 b를 주지 않고 점 몇 개만 준 뒤 a·b를 구하는 문제와 같습니다.

y = f(x)
x(입력: 소득·연체 횟수…)를 넣으면 y(출력: 승인/거절)가 나오는 함수
규칙 기반
f의 모양과 숫자를 사람이 정함 — "소득 ≥ 3,000이면 승인"
머신러닝
f의 모양만 정하고, 안의 숫자는 과거 데이터(x와 정답 y)를 보고 컴퓨터가 채움
학습
그 빈칸 숫자를 채우는 과정. 다 채우면 평범한 함수가 됨
숫자로 한 번 해 보기

점 (1, 3), (2, 5), (3, 7)을 보고 "y = 2x + 1"이라는 규칙을 찾아내는 것이 학습입니다. 찾은 뒤 x = 10을 넣으면 21을 예측합니다.

조수

수학 문제를 거꾸로 푸는 거네요. 답을 잔뜩 보고 식을 찾는 것!

은행에서는

전통적 방식은 데이터를 보고 전문가와 담당 직원의 의견을 반영해 판단 기준을 직접 입력합니다. 머신러닝은 데이터와 과거 결과(정상 상환·연체)로 판단 기준을 자동으로 만들고, 그중 결과가 가장 좋은 기준을 고릅니다.[1]

사람이 쓴 규칙은 왜 그렇게 판단했는지 분명하고 결과를 예상하기 쉽지만, 새로운 상황에 유연하지 않습니다. 머신러닝은 복잡한 패턴과 새 데이터에 맞춰 가지만, 판단 이유를 설명하기 어렵고 과거 기록이 많이 필요합니다.[1]

데이터 분할과 돌아가며 시험 — 외운 것과 배운 것

방법: 공부용·점검용·시험용 나누기, 다섯 번 돌아가며 시험연구실: 봉인한 시험지

이 칸의 결론공부한 문제로 본 점수는 실력이 아닙니다. 처음 보는 데이터로 여러 번 시험해야 진짜 실력이 보입니다.

먼저왜 이 방법을 쓰나

모델이 연습 문제(훈련 데이터)에서 100점을 받아도, 문제를 외운 것인지 원리를 배운 것인지는 처음 보는 문제로 시험해야 압니다. 그런데 시험을 한 번만 보면 문제가 쉬웠는지 운이 좋았는지 모릅니다. 그래서 데이터를 여러 조각으로 나눠 돌아가며 시험 보는 것이 교차 검증입니다.

쉽게 말하면 모의고사를 다섯 번 보고 평균을 내면, 한 번 본 점수보다 실력을 더 정확히 압니다.

수식수학 수식을 어려워하는 조수가 대신 물어봅니다

조수

5겹(5-fold)
데이터를 5조각으로 나눠, 한 조각은 시험 · 네 조각은 공부를 5번 바꿔 가며 반복
평균 점수
5번 점수의 평균 = 처음 보는 데이터에서의 실력 추정
숫자로 한 번 해 보기

데이터 100건 → 20건씩 5조각. 다섯 번의 시험 점수가 0.80, 0.84, 0.78, 0.82, 0.86이면 평균 = 4.10 ÷ 5 = 0.82. 점수가 0.78~0.86으로 흔들리는 폭도 함께 봅니다.

조수

한 번 점수는 운일 수 있으니, 다섯 번 평균을 보고 흔들리는 폭도 같이 보는 거군요.

연구실에서는

연습 문제만 달달 외운 학생은 연습 문제로 치면 100점이지만, 처음 보는 시험지에서는 무너집니다. 그래서 시험지는 따로 봉인해 둡니다.

머신러닝에서는

공부한 문제만 너무 잘 외워 처음 보는 문제를 못 푸는 상태를 과적합이라고 합니다. 교안은 데이터를 공부용·점검용·시험용으로 60:20:20이나 70:15:15로 나누고, 데이터가 적으면 돌아가며 시험 보는 방법(교차 검증)을 쓰라고 합니다.[1]

1

풀이

  1. K = 1이면 모든 훈련 기록이 자기 자신을 이웃으로 삼아 훈련 정확도가 100%입니다. 예외 8%까지 외워 경계가 울퉁불퉁해집니다.
  2. 다섯 번 돌아가며 시험은 600건을 다섯 묶음으로 나눠, 한 묶음씩 번갈아 검증용으로 쓰고 나머지로 학습합니다. 다섯 점수의 평균과 흩어짐을 함께 봅니다.[1]
  3. K는 돌아가며 시험 점수로 고르고, 봉인한 시험 데이터 400건은 마지막에 한 번만 씁니다. 시험 점수로 K를 고르면 시험지를 미리 본 셈입니다.
  4. K가 너무 작으면 과적합, 너무 크면 경계가 뭉개지는 과소적합입니다.[1]

수식으로 보기

k번 돌아가며 시험 점수 = (1/k) Σi=1..k 정확도(묶음 i로 검증, 나머지로 학습)

홀드아웃(한 번 나눠 한 번 평가)은 빠르지만 나누는 방법에 따라 결과가 흔들립니다. 부트스트랩은 복원 추출로 여러 표본을 만들어 성능의 분포를 봅니다.[1]
