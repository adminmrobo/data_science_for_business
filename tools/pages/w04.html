왜 도구와 알고리즘을 따로 배우나

1. 도구가 프로젝트를 좌우한다

교안은 도구 선택이 분석 프로젝트의 성공을 결정하는 핵심 요소라고 말합니다. 맞지 않는 도구를 고르면 분석 효율과 결과 품질이 크게 떨어집니다.[1]

2. 규칙을 누가 만드는가

전통적 프로그래밍은 사람이 규칙을 적고, 머신러닝은 데이터와 과거 결과에서 규칙을 찾습니다. 같은 대출 심사라도 만드는 방식이 다릅니다.[1]

3. 문제 유형이 모델을 고른다

3주차에서 정한 분류·예측·군집·연관·최적화 유형마다 어울리는 알고리즘과 평가 지표가 있습니다.[1]

규칙 기반과 머신러닝 — 신용대출 심사

비교: 사람이 쓴 규칙 vs 데이터에서 배운 규칙교안 사례: 은행 신용대출

은행에서는

전통적 방식은 데이터를 보고 전문가와 담당 직원의 의견을 반영해 판단 기준을 직접 입력합니다. 머신러닝은 데이터와 과거 결과(정상 상환·연체)로 판단 기준을 자동으로 만들고, 그중 결과가 가장 좋은 기준을 고릅니다.[1]

머신러닝에서는

사람이 쓴 규칙은 왜 그렇게 판단했는지 분명하고 결과를 예상하기 쉽지만, 새로운 상황에 유연하지 않습니다. 머신러닝은 복잡한 패턴과 새 데이터에 맞춰 가지만, 판단 이유를 설명하기 어렵고 과거 기록이 많이 필요합니다.[1]

생성 AI로 치면

3검증

데이터 분할과 교차 검증 — 외운 것과 배운 것

방법: 훈련·검증·시험 분할, 5겹 교차 검증연구실: 봉인한 시험지

연구실에서는

연습 문제만 달달 외운 학생은 연습 문제로 치면 100점이지만, 처음 보는 시험지에서는 무너집니다. 그래서 시험지는 따로 봉인해 둡니다.

머신러닝에서는

공부한 문제만 너무 잘 외워 처음 보는 문제를 못 푸는 상태를 과적합이라고 합니다. 교안은 데이터를 공부용·점검용·시험용으로 60:20:20이나 70:15:15로 나누고, 데이터가 적으면 돌아가며 시험 보는 교차 검증을 쓰라고 합니다.[1]

풀이

  1. K = 1이면 모든 훈련 기록이 자기 자신을 이웃으로 삼아 훈련 정확도가 100%입니다. 예외 8%까지 외워 경계가 울퉁불퉁해집니다.
  2. 5겹 교차 검증은 600건을 다섯 묶음으로 나눠, 한 묶음씩 번갈아 검증용으로 쓰고 나머지로 학습합니다. 다섯 점수의 평균과 흩어짐을 함께 봅니다.[1]

  4. K가 너무 작으면 과적합, 너무 크면 경계가 뭉개지는 과소적합입니다.[1]

데이터 과학에서는

세 숫자로 봅니다. 지지도 = 둘 다 산 손님의 비율. 신뢰도 = 라면을 산 손님 중 달걀도 산 비율. 향상도 = 신뢰도 ÷ 달걀을 산 손님의 비율. 향상도가 1보다 크면 우연보다 함께 잘 팔린다는 뜻입니다.[1]
