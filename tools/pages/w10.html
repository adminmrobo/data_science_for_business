왜 이 세 도구인가

1. 확률이 필요하다

스팸인가 아닌가, 합격인가 불합격인가. 회귀식의 출력은 −∞~+∞라 그대로는 확률이 아닙니다. 시그모이드로 0~1에 가둡니다.[1]

2. 설명이 필요하다

"나이 30세 이상이고 소득 5,000만 원 이상이면 대출 승인" 같은 규칙은 고객과 규제기관에 그대로 보여 줄 수 있습니다. 의사결정나무가 만드는 것이 이런 규칙입니다.[1]

3. 좋은 재료가 필요하다

때로는 복잡한 알고리즘보다 좋은 특성 하나가 더 효과적입니다. 다만 특성이 늘면 과적합도 늘어 벌점이 함께 필요합니다.[1]

1확률

로지스틱 회귀 — 직선 점수를 S자 확률로

방법: 점수 → S자 곡선 → 0~1 확률데이터: 공부시간-합격 40명(예시)

일상으로 치면

교안의 공부시간과 합격 확률입니다. 처음에는 확률이 낮다가 어느 구간에서 빠르게 오르고, 결국 거의 확실해집니다. 아무리 더 공부해도 100%를 넘지는 않습니다(포화).[1]

머신러닝에서는

w₁은 공부 시간이 합격에 얼마나 크게 영향을 주는지(음수면 반대 방향), w₀는 곡선 전체를 좌우로 옮기는 기준점입니다. 컴퓨터는 "틀린 정도"를 나타내는 점수가 가장 작아질 때까지 w₀, w₁을 조금씩 고쳐 가며 찾습니다.[1]

풀이

  1. w₁을 키우면 S자가 가팔라지고(결정이 단호해짐), w₀를 바꾸면 곡선이 좌우로 이동합니다. 곡선이 0.5를 지나는 공부시간이 결정 경계(−w₀ ÷ w₁)입니다.
  2. "비용 최소화"를 누르면 경사하강으로 로그 손실이 가장 작은 w₀, w₁을 찾습니다. 정확도 대신 비용을 줄이는 까닭은, 비용이 매끄럽게 변해 조금씩 고쳐 갈 방향을 알려 주기 때문입니다.
  3. 출력 0.7은 "70% 확률로 합격"으로 바로 읽힙니다. 7주차의 임계값 이야기가 여기에 그대로 붙습니다.[1]

이 칸의 한계: 결정 경계가 직선(특성 하나면 점 하나)이고, 계수만으로는 현장 담당자에게 "왜"를 규칙으로 말해 주기 어렵습니다. → ②칸 의사결정나무

비용함수(로그 손실)

비용 = −(1/n) Σ [ y·log p + (1 − y)·log(1 − p) ], p = σ(w₀ + w₁x)

정답이 1인데 p가 0에 가까우면 비용이 매우 커집니다. 교안의 활성함수 그림(시그모이드·tanh·ReLU 등)은 CS231n 강의 자료를 인용한 것입니다.[1]

5벌점
릿지와 라쏘 — 계수 다이어트와 특성 선택

    
방법: 틀린 정도 + 계수가 크면 벌점Ridge: L2(제곱) · Lasso: L1(절댓값)

  

  

    
일상으로 치면
교안의 양념 비유입니다. 릿지는 모든 양념을 조금씩 써서 조화로운 맛을, 라쏘는 핵심 양념 두세 개만 골라 깔끔한 맛을 냅니다. α는 양념 조절의 강도입니다.[1]

    
머신러닝에서는
릿지는 "계수를 제곱해 더한 값"에, 라쏘는 "계수 크기를 그냥 더한 값"에 벌점을 줍니다. 라쏘는 덜 중요한 계수를 아예 0으로 만들어 쓸 재료를 골라 줍니다. α가 클수록 벌점이 세지며, 알맞은 α는 공부용 데이터 안에서 돌아가며 시험해(교차 검증) 찾습니다.[1]

금융 데이터에서는 이동평균, 변동성, 모멘텀, RSI 같은 도메인 특성이, 시계열에서는 지연(lag)·차분·계절성 분해가 효과적입니다. EDA → 가설 → 특성 생성 → 검증 → 개선을 반복하고, 어떤 특성을 왜 만들었는지 기록합니다. 전처리·특성공학·모델을 Pipeline으로 묶으면 시험 데이터가 섞여 드는 실수를 줄입니다.[1]
한계: 특성 선택 도구(SelectKBest 등)는 빠르지만 특성 간 상호작용은 보지 못합니다.[1]

    
생성 AI로 치면
대형 언어모델 학습에도 가중치 감쇠(weight decay)라는 L2 계열 벌점이 거의 언제나 들어갑니다. 계수(가중치)가 커져 작은 입력 변화에 출력이 날뛰는 것을 막는 같은 생각입니다.
비유의 한계: 언어모델은 특성을 사람이 만들지 않고 모델이 스스로 표현을 학습합니다.
